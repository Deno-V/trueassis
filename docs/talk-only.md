# 纯对话操作手册（Talk-Only）

> 目标：**你永远不需要碰代码、不需要记命令、不需要打开文件。**
> 只跟 AI 说人话。这份文档告诉你能说什么，以及 Agent 会怎么做。

把这个仓库交给任何 Agent（Codex / CodeBuddy / Claude Code / Trae / Cursor），
它会读 `AGENTS.md` 然后自行操作。你只管说话。

---

## 一、每天最常用的三句话

| 你说 | Agent 做什么 | 你得到 |
|---|---|---|
| **"今天该干什么"** | `recur run` + `brief` + `profile` | 逾期项、今日到期、≤3 条带理由的建议 |
| **"我只有 20 分钟，还挺累"** | `next --energy low --time 20` | 匹配你当下状态的任务，不会推 3 小时的硬活 |
| **"今天结束了"** | `wrap daily` | 日报已生成，问你复盘三问，自动归档+体检 |

说法不必精确。"在吗""帮我看看""我闲着""有啥要做的"都会触发简报。

## 二、按意图查（你想干什么 → 你怎么说）

**先说一件重要的事**：下面的表格是**举例，不是清单**。
系统不认识任何特定领域——没有"体重功能"、没有"跑步模块"。
是 AI 读懂你的话，然后决定该改哪个文件。

所以你说什么都行，包括表里没有的：
「喝了 8 杯水」「背了 50 个单词」「练了 40 分钟琴」「猫打完疫苗了」
「妈的生日礼物买好了」「那个需求评审推迟了」——**处理方式完全一样**。

### 记录新事项

| 你说 | 效果 |
|---|---|
| "我要在周五前完成金融数据合并，大概 3 小时" | 建任务，ddl 周五，估时 3h |
| "记一下这几件事：处理报销、买机票、给妈打电话" | 一次收 3 条（`capture`），然后问你哪些要定 ddl |
| "我想读《XX》，有空再说" | 进愿望池（someday），不污染待办列表 |
| "周六要骑车去天津，提前三天提醒我" | 建 event，`remind_before: 3d` |
| "以后每周二四六都要运动" | 建重复任务，`rule: weekly:tue,thu,sat` |
| "我刚骑了 30 公里，膝盖有点酸" | 记进健康日志（这是事实，不是待办） |

**你不必区分"任务/项目/想法"**——描述清楚，Agent 会判断。
说"我要做 X"→任务；说"要是能 X 就好了"→愿望池；说"我刚做了 X"→日志。

### 查询

| 你说 | Agent 做什么 |
|---|---|
| "列出所有待办" | `list` |
| "工作上这周有什么" | `list --domain work --due-in 7` |
| "我上次骑行是什么时候" | `search 骑行`（查任务+日志+日报+归档） |
| "金融那个事进展到哪了" | `show` 该条目，念给你听 |
| "这个月都干了啥" | `journal monthly` |
| "有什么快烂掉的事" | `brief` 的停滞区 |

### 推进与收尾

| 你说 | Agent 做什么 |
|---|---|
| "我开始做金融数据了" | `start <id>` |
| "eval 分支推完了" | `done <id> --note "..."` |
| "报销那事不办了，公司改政策了" | `cancel --reason "公司改政策"` |
| "骑行改到下周" | `defer --to +1w` |
| "PM 数据要等对方给字典" | `block --by "等对方给数据字典"` |
| "这个先不做了，放愿望池" | `someday <id>` |
| "把金融那个提到最高优先级" | `edit --set priority=P0` |

### 出错了

| 你说 | Agent 做什么 |
|---|---|
| **"错了 / 撤销 / 回退 / 不对"** | **`undo`** —— 回滚上一次写操作 |
| "刚才都改了什么" | `history` |
| "回到今天上午的状态" | `history` 找检查点 → `undo --to N` |

⚠️ **这是你的安全网**。因为你不碰代码，Agent 改错了你唯一的修复手段就是让它 `undo`。
系统在每次写操作前都存了完整快照（保留最近 30 次），包括文件移动和批量联动。
放心说"撤销"，不用担心改坏。

### 复盘与画像

| 你说 | Agent 做什么 |
|---|---|
| "陪我做周复盘" | `wrap weekly` + 逐条陪你决策 |
| "我上午效率最高，下午就废了" | 写进画像的「精力节律」，以后建议会照此安排 |
| "别给我安排太满，我讨厌被塞爆" | 写进画像的「雷区」 |
| "这个季度我只想搞定金融平台" | 写进「当期重心」，相关任务会加权 |

**画像越具体，建议越准。** 空画像只能给泛泛建议。

## 三、提醒是怎么来的

这是最需要理解的一点：**AI 没有后台进程，它只在你跟它说话时才活着。**
所以"到点提醒"必须靠仓库外的东西唤起。系统分三层：

```
第 1 层  数据层（已内建，永远生效）
        ddl 分区、remind_before 提前预警、停滞检测、项目空转检测
        → 保证"信息不丢"，但需要有人来看

第 2 层  会话层（靠 Agent 遵守协议）
        你一开口，它就先跑 brief 主动汇报
        → 最可靠，因为不依赖任何定时器

第 3 层  时钟层（需要装，二选一或都装）
        A. 工具定时任务（如 CodeBuddy automation）
           → Agent 会思考，给带理由的建议
        B. 系统 cron：bash tools/install-reminders.sh
           → 不依赖 AI 工具，开机生效，弹 macOS 桌面通知
             但它只能说"有 N 项到期"，不会思考
```

**推荐 A + B 一起装**：cron 负责戳你一下（保证不漏），AI 负责想清楚（保证有用）。
桌面通知弹出来 → 你去问 Agent → Agent 给带理由的建议。

装第 3 层（一次性，之后忘掉它）：

```bash
bash tools/install-reminders.sh --dry-run   # 先看会装什么
bash tools/install-reminders.sh             # 装
```

这是**唯一**需要你敲一次命令的地方——因为修改系统定时任务超出了仓库范围，
让 Agent 自动改你的 crontab 不是好设计。装完就再也不用管了。

macOS 还需在「系统设置 → 隐私与安全性 → 完全磁盘访问权限」里给 cron 授权。

## 四、如果 Agent 表现不对

| 症状 | 说什么 |
|---|---|
| 上来就问一堆问题，不先看数据 | "先跑 brief 再说" |
| 一次给你七八条建议 | "只给我三条，按 AGENTS.md 的格式" |
| 建议没有理由 | "每条说清楚为什么是它" |
| 直接手改 md 文件而不用 CLI | "用 ./tools/assis，不要手改文件" |
| 改坏了数据 | "undo" |
| 完全不知道自己该干什么 | "读 AGENTS.md" |

`AGENTS.md` 是所有 Agent 的行为契约。它跑偏时，让它重读。

## 五、给你的建议

1. **诚实报告状态**。谎报精力和可用时间 → 得到错误建议 → 任务失败 → 你会放弃这个系统。
2. **每天写三行复盘**（Agent 会问你）。这是画像唯一的原料，也是系统"越用越懂你"的前提。
3. **每周至少放弃一件事**。不能优雅放弃的清单会变成负债，让你不敢打开。
   `cancel` 在这个系统里是正向行为，理由会喂给画像。
4. **想到就说**，不要攒着。收集的成本越低，系统越可信。
5. **先填画像**（说一句"帮我填画像"，Agent 会问你几个问题）。
   空画像状态下，建议质量会明显偏低。
